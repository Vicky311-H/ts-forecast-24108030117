核心纪律：预测 $t+h$ 时只许用 $t$ 及之前的信息。 这一条比任何模型技巧都重要——它同时决定了你的指标是否可信、你的报告是否诚实。

1. 认识数据：从"事件流"到"时间序列"

flow.csv 是车辆级交通检测数据：每辆车驶过检测器记一行， 共 503,768 行，含 Speed (mph)、Headway (s)（车头时距，与前车到达时刻之差）、 Gap (s)（车头空距，与前车尾部离开之差）。

类比——把雨滴装进量筒：雨是一滴一滴落的（事件级，间隔不均匀），气象站报的是"每小时降雨量" （规则网格）。检测器每毫秒都可能记到车，而所有时序模型都要求等间隔采样。 所以第一步必须聚合：把每小时全部过车记录压成一个平均车速。 
# 事件级 -> 时间序列：清洗 + 聚合（本课代码第1步）
speed = df["Speed (mph)"].astype(float)
df = df.loc[speed.between(10, 80)]        # ① 剔除传感器异常读数
df["day"], df["hour"] = df["Date"].dt.date, df["Date"].dt.hour
hourly = df.groupby(["day", "hour"])["Speed (mph)"].mean()   # ② 逐时平均
# 结果: 8 天 x 24 小时 = 192 个等间隔点，季节周期 s=24

清洗剔除了 8,378 条（1.66%）速度落在 $[10,80]$ mph 之外的记录——真实检测器会输出 121 mph 这类违背物理的读数，那是传感器故障，不是超级跑车。

图1 上：192 点完整序列；下：8 天同小时平均的"典型日曲线"，两峰两谷的日周期

典型日曲线讲了一个直观的故事：凌晨车少、车速接近自由流（约 38 mph）；7-8 点早高峰跌到 27-28 mph；傍晚 16-18 点再次跌到 29 mph；夜里恢复。这就是季节性最生活化的样子。

数据里的 8 天并不连续（分散在 2018-02-02 至 02-27 之间）。因为每天内部都是完整 24 小时、"每日一循环"的结构真实存在，我们把 8 天按顺序拼成 192 点序列、以 24 为周期建模。 这是教学上的合理简化；做研究时必须先检查采样连续性，并在报告里写明。

2. 平稳性：给序列做"体检"，以及一个高频误解

2.1 弱平稳的三个条件

$$\text{① } E[y_t] = \mu \quad \text{② } \mathrm{Var}(y_t) = \sigma^2 \quad \text{③ } \mathrm{Cov}(y_t, y_{t-k}) \text{ 只依赖 } k \text{，不依赖 } t$$

为什么模型要求平稳？模型的工作是"从历史归纳规律，再外推到未来"，前提是 历史规律 = 未来规律。若均值不断漂移（通胀让物价整体上移）， 你学到的"平均水位"对未来就是错的。平稳性 = 保证"过去的统计规律可安全外推"。

2.2 ADF 检验与本例的真实结果

ADF 检验的原假设是"存在单位根"（随机游走式不平稳），$p<0.05$ 时拒绝。实测：

序列ADF 统计量p 值结论
原始序列-7.452$5.62\times10^{-11}$平稳 ✅
一阶差分后-6.754$2.90\times10^{-9}$平稳 ✅
最高频的概念错误：ADF 说"平稳"，不代表序列没有可建模的结构！ ADF 只检验单位根（随机趋势）型不平稳，不检验季节型不平稳。 我们的序列围绕约 33 mph 的固定水位回归，没有随机漂移，所以 ADF 判平稳； 但它内部藏着强烈的 24 小时周期摆动。所以模型照样要做季节处理（差分或分量的季节头）。 "平稳"和"有季节性"是两个正交的概念。
图2 上/中：原始与差分序列及 ADF 结果；下：24 小时滚动均值随昼夜大幅摆动——ADF 测不到的"均值层周期结构"

3. ACF 与 PACF：给序列测"记忆力"

类比——山谷里的回声：ACF 是你对山谷喊一声听总回声， $y_t$ 与 $y_{t-k}$ 的总体相关里混着"中间各步传导"的间接影响；
PACF 则把中间所有"传话人"都剔除后，看 $y_{t-k}$ 对 $y_t$ 的直接影响。
$$\rho(k) = \frac{\mathrm{Cov}(y_t,\, y_{t-k})}{\sqrt{\mathrm{Var}(y_t)\,\mathrm{Var}(y_{t-k})}} \quad \text{(ACF)}$$
模型ACFPACF记忆机制
AR(p)拖尾（衰减/振荡）lag p 处截尾当前值 = 历史值的线性组合
MA(q)lag q 处截尾拖尾当前值 = 历史噪声的线性组合
ARMA(p,q)拖尾拖尾混合

图3 的 ACF 给出教科书级证据：lag 24 处显著第二高峰，整条 ACF 呈 24 步周期的波浪。 这就是"日周期"在相关性层面的指纹，也是我们把周期定为 $s=24$、把 look_back 设为 24 的依据。

图3 原始序列的 ACF（lag24 峰 = 日周期指纹）与 PACF；差分后的 ACF/PACF

4. 分解：把序列拆成三层

$$y_t = \underbrace{T_t}_{\text{趋势}} + \underbrace{S_t}_{\text{季节}} + \underbrace{R_t}_{\text{残差}} \quad(\text{加法}) \qquad\qquad y_t = T_t \times S_t \times R_t \quad(\text{乘法})$$

成分含义本例中的样子
趋势 $T_t$长期缓慢方向性变化基本平坦（8 天内无系统升降）
季节 $S_t$固定周期重复波动周期 24h 的规则波形，本例的主角
残差 $R_t$去掉前两者的随机部分高峰时段明显更大
加法还是乘法？振幅恒定 → 加法；水位越高摆得越大 → 乘法。 本例高峰时段（车速低、车流密）残差更大，方差随水平增长，严格说更接近乘法结构（或取对数后用加法）。 多数正值且幅度随水平变化的序列（销量、客流、流量）都属此类。
图4 观测 / 趋势 / 季节（周期 24）/ 残差。季节项是绝对主角
分解不只用来"看"，还能用来"建模"：DLinear 的核心思想就是把序列拆成趋势与季节两条线， 各自用一个线性头拟合，再相加。本课代码里的 DLinear 就是这个结构 （区别是它用因果移动平均做分解，更适合在线预测）。这是"结构先验"胜过"盲目加深度"的典范。

5. 评估协议：时间不能被打乱

5.1 随机划分 = 作弊

在时间序列上用 train_test_split(shuffle=True) 或普通 K 折， 等于"用明天训练、去回忆昨天"——这不是预测，是回忆。指标会漂亮得离谱，上线即崩。 这叫数据泄露（data leakage），是时序项目失败的第一大原因。
泄露形式错误做法正确做法
① 划分泄露随机打乱后划分按时间切分，测试在训练之后
② 归一化泄露用全序列均值/方差做标准化只用训练段统计量，冻结后套到测试段
③ 特征泄露滚动统计窗口含当前或未来时刻窗口右端点严格 < 预测目标时刻
④ 移动平均泄露用居中窗口做平滑用因果（只看过去）窗口
第 ④ 条是本课代码里特意处理的：trailing_ma() 只用到当前位置为止的数据。 写成 np.convolve(x, np.ones(k)/k, mode='same') 看起来更"标准"，但它会看到未来 2 个点—— 在本课这种短序列上，这几个点几乎就是答案本身。

5.3 指标：为什么主推 MASE

$$\mathrm{MASE} = \frac{\displaystyle\frac{1}{n}\sum_{t} |y_t - \hat{y}_t|}{\displaystyle\frac{1}{m}\sum_{j}|y_j - y_{j-1}|}$$ 分母是训练段朴素预测的平均绝对误差。

指标量纲优点缺点
MASE无量纲跨数据集可比（这是 GIFT-Eval 榜单的通用尺），尺度不变不反映大误差惩罚
MAE与 y 相同直观、单位可解释不可跨数据集比
RMSE与 y 相同平方惩罚大误差对异常值敏感
MAPE百分比无量纲真值近 0 时爆炸；跨序列平均会失真
本课代码用 naive_scale() 在训练段上算 MASE 分母。 如果用全序列算分母，测试集信息就漏进了训练——这正是第 5.1 节第 ② 条泄露的隐蔽版本。 MAPE 之所以逐步被 MASE 取代，正是因为它对"接近零的目标"（流量、销量、缺货）会给出荒谬数值。

6. 模型演进：三代范式（本课核心）

6.1 第一代：统计模型——从主角退居"基线与可解释性"

ARIMA / 指数平滑 / Theta 在今天仍有不可替代的价值，但角色变了：

还用不用用在哪里
✅ 必须用Seasonal Naive 作为必备基线；GIFT-Eval 榜单中它就是相对 MASE = 1.00 的参照系。任何新模型先过它这一关。
✅ 仍常用样本极少、需要预测区间与统计推断的场景；金融/计量类要求可解释的任务；作为集成的一个分量。
⚠️ 地位下降作为"最强模型"的候选——在周期性强、样本中等的数据上，常被一个带归一化的线性模型超过。

本课代码保留 Seasonal Naive 与 Naive 作为基线，但不再把 Holt-Winters / SARIMA 放进对决名单：它们在 192 点的数据上既无优势、又把叙事重心拉回第一代。

6.2 第二代：RNN/LSTM 为什么退场

你的直觉是对的，RNN 在时序预测中已基本退场。原因不是它"不够好"，而是三条硬伤叠加：

硬伤机理后果
递归误差累积多步预测必须把自己的预测喂回输入步数一多就漂移，Moirai/Chronos-2 正是用"非自回归一次出完整 horizon"来规避
训练不可并行$h_t$ 依赖 $h_{t-1}$，时间步之间串行GPU 吃不满；Patch/Transformer 可完全并行
长依赖被结构性削弱信息要逐步传过 $t$ 步Day 3 已算过：有效记忆 ~10-20 步，RNN 原生的衰减乘积无法根治
更关键的实证：连"深度学习时代"内部，RNN 也常输给 线性 模型。 Autoformer（2021）自己的消融实验就发现 DLinear 打赢了 Informer / Transformer； GIFT-Eval 榜单（arXiv:2410.10393）总榜第一是 PatchTST，不是任何 RNN。
结论：RNN 的历史价值在理解序列建模与记忆机制（Day 3 的教学目的）， 而非 2026 年的工程首选。它留在 Day 3，留在本章的"为什么"里，不留在对决名单里。

6.3 第三代 A：线性模型的复兴（最反直觉、也最重要）

2022 年 RevIN（可逆实例归一化）解决了分布漂移问题，2023 年 DLinear 掀起"线性反超 Transformer"的辩论。 核心结构其实极简：

$$\text{NLinear: } \hat{y} = \underbrace{(w \cdot (x - x_{last})) + b}_{\text{在"相对末值"空间预测}} + x_{last}$$ $$\text{DLinear: } \hat{y} = \underbrace{w_1 \cdot \mathrm{MA}(x)}_{\text{趋势头}} + \underbrace{w_2 \cdot (x - \mathrm{MA}(x))}_{\text{季节头}}$$

两个关键设计值得单独讲：

① 实例归一化（NLinear 的关键）：不同序列、或同一序列的不同"水位"下， 分布位置差别很大。减去窗口末值再建模，等于强迫模型只学形状而不学水位， 迁移性大幅改善。
② 趋势-季节解耦（DLinear 的关键）：趋势与季节混在一起用一个头拟合，会互相干扰。 拆成两个头各自拟合，参数各自专注，反而更准。
2025 年的独立实证（UrbanAI 2025 挑战赛，arXiv:2512.10866，长程室内温度预测）
在标准化训练/验证/测试划分下的测试 MAE：
  NLinear 0.2461 < DLinear 0.2811 < Linear 0.2862 ≪ Autoformer 0.3598 < Transformer 0.8342 ≈ Informer 0.8342
值得注意：Transformer 的训练 MSE 极低（0.0330），测试却崩到 1.4371—— 典型的在小样本上把训练集背下来、毫无泛化。结论不是"线性永远赢"， 而是"归纳偏置选对了，容量小反而赢"。
本课代码用闭式岭回归实现这一族：$W = (X^\top X + \alpha I)^{-1} X^\top Y$。 好处是无需 GPU、秒级出结果、结果确定可复现（不依赖随机初始化）， 非常适合在课堂上反复追问"这个结论稳不稳"。$\alpha$ 由训练段尾部的内层验证自动选择， 不用测试集调参。

6.4 第三代 B：Patch + Transformer（当前的主力架构）

把长序列切成 patch 再做注意力，是 2023 年以来最成功的架构改进。

原始逐点输入:  [x1][x2][x3][x4][x5][x6][x7][x8] ... 注意力代价 O(L^2)，且单个点信息量太少
                     ↓ patch 化 (patch_len=P, stride=S)
patch 输入:     [x1..x4][x5..x8][x9..x12] ...  序列长度 L/P，语义更集中
                     ↓ 线性嵌入 -> Transformer -> 线性头
预测:           未来 H 步
代表模型年份/会议核心贡献
PatchTSTICLR 2023通道无关的 patch 分割 + 线性头；GIFT-Eval 总榜第一（相对 MASE 0.86）
iTransformerICLR 2024反转注意力维度：把"变量"当 token，捕捉跨变量依赖
TimeMixerICLR 2024多尺度时间混合，可分解式建模
ModernTCNNeurIPS 2024大核卷积 + 可变大感受野，卷积复兴路线
TimeXer2024显式建模外生变量（exogenous）的 token 化
TimesNetICLR 2024用 FFT 捕捉多周期（周/月/年）叠加
一个值得玩味的数学事实：如果把窗口切成 patch 后仅仅拉平再接一个 全秩线性头，得到的映射在数学上与"直接对窗口做线性回归"完全等价 （本课代码最初就踩了这个坑，两行结果一模一样）。
这说明：PatchTST 的增益不来自 patch 本身，而来自 patch 嵌入与注意力的非线性/参数共享结构。 "分片"是必要不充分的技巧——理解这一点，就理解了为什么"照抄结构"不等于"迁移有效"。

6.5 第三代 C：时间序列基础模型（TSFM，2024-2026 的主角）

在超大规模真实时间点（百亿到万亿级）上预训练，一个模型直接零样本（zero-shot）预测 任意未见过的序列，不必逐序列训练。

6.6 一句话带过：概率预测与扩散模型

点预测给你一个数，概率预测给你一个分布——这在库存、容量规划、风险决策里才是真正需要的输出。 技术路线有两条：分位数/集成（Chronos-2 的 21 个分位数、集成模型）与 扩散模型（Diffusion 类方法把预测当作生成任务，如 TimeGrad / CSDI 一脉）。 评估指标从 MAE 换成 CRPS 或分位数损失。GIFT-Eval 榜单也同时报告 CRPS。

7.3 三个诚实的结论

① 线性模型的收益来自"结构对"，不是"容量大"
DLinear（0.371）比 Ridge-AR（0.543）好近 1/3，但两者都是线性映射。差别在于 DLinear 把趋势与季节拆开、各用一个头——结构先验而非参数规模带来了增益。

② NLinear 的实例归一化在本例上没帮上忙（0.625，劣于 Ridge-AR）
这与 UrbanAI 2025 的结论并不矛盾：NLinear 的优势出现在分布位置差异大的设定。 本数据 192 点、单一水位、噪声很小，归一化的收益被"损失末值信息"抵消。 照搬论文里的组件、却不知道它为什么有用，是最常见的误用方式。

③ 折间标准差暴露了"赢家"的不确定性
DLinear 的 CV MAE 标准差高达 0.371（最大）。单看折均值它是冠军， 但"±0.371"意味着换一周数据结论可能翻转。报告只给均值不给标准差，是选择性汇报。
图9 可解释性：各输入位置对未来 24 步的平均 |权重| 贡献。线性模型的权重可以直接读
图9 是本课最有教学价值的一张图：线性模型的权重是可以直接读懂的。 哪个时间位置对预测重要，一目了然。这种可解释性不是"简单模型的缺点"， 而是很多场景下真正的需求（要向监管、向业务方解释"为什么这么预测"）。

9. 深化：多步策略、预测区间、统计比较

9.1 多步预测的两种策略

策略做法优点缺点
递归式预测 1 步 → 喂回 → 再预测下一步只需一个模型误差累积，早期小错滚雪球
直接式每个 horizon 单独建模无累积模型数量 ×h

本课代码用直接多输出（窗口 $\to$ 24 步一次性回归），这也是现代 TSFM （如 Moirai、Chronos-2）一次输出整个 horizon 的理由。

9.2 点预测 ≠ 预测

完整的预测要回答"有 95% 把握落在哪个区间"。统计模型天然给区间（get_forecast().conf_int()）， TSFM 用分位数（如 Chronos-2 的 21 个 P1–P99）实现同一件事， 深度模型则需要分位数回归 / MC Dropout / 深度集成等额外技巧。

区分置信区间（对参数不确定性的度量）与预测区间 （对未来单个观测的度量，更宽）。另外，评估区间质量的指标不是 MAE，而是 CRPS / 分位数损失 / 覆盖率——区间要"宽而不虚"。

9.3 模型之间的差异是否显著？Diebold-Mariano 检验

如果模型 A 的 MAE 是 0.555、模型 B 是 0.813，你能断言 A 更好吗？不能—— 需要检验两者的误差差异 $d_t = e_t^A - e_t^B$ 的均值为零是否被拒绝。 DM 检验正是为此设计的，并且需要小样本修正（Hansen 修正）才可靠。

本课作业把 DM 检验作为必做项，正是为了训练学生不要用"指标好看"代替"差异显著"。

面试三连（2026 版）

Q1: "2026 年做时序预测你会用什么模型？"
A: 先问数据：样本量、频率、是否有强季节、是否多变量、能否用外部协变量。 样本少或多序列 → 零样本 TSFM（Chronos-2，注意许可）；中高频单序列 → PatchTST/iTransformer； 周期性强且中小规模 → NLinear/DLinear 往往性价比最高。永远先跑 Seasonal Naive 基线。

Q2: "为什么线性模型能打败 Transformer？"
A: 因为时序数据信噪比低、样本量远小于 CV/NLP，复杂模型会把训练集背下来（UrbanAI 2025 中 Transformer 训练 MSE 0.033、测试 1.437 就是典型过拟合崩塌）。线性模型的强归纳偏置 （平滑、局部性、归一化/分解）恰好匹配时序结构，偏差-方差权衡占优。

Q3: "RNN/LSTM 在时序预测里过时了吗？"
A: 工程上基本过时（递归误差累积、无法并行、长期被 Transformer 与线性模型双重压制）； TSFM 全部基于 Transformer 而非循环结构。但它是理解序列建模与记忆机制的必经之路， 且在流式小样本、超低延迟、资源受限的边缘场景仍有其位置。

10. 课后作业（防 AI 代写与抄袭设计）

作业：按你的学号领取一份"专属任务书" ★★★★★

10.1 设计思路：为什么普通作业挡不住 AI

普通时序作业（"用 LSTM 预测 flow.csv 的车速"）在 2026 年几乎失效： AI 三十秒就能生成一份结构完整、指标漂亮、但没有任何思考痕迹的代码与报告， 而批改者很难逐行分辨。本作业因此不使用统一题目，改为 由学号确定性派生一份个性化任务书，并配四道"指纹型"机制。
机制具体做法能防住什么
① 学号派生任务书学生运行 hw_task_selfservice.py --sid <学号>， 派发目标变量（speed / headway / gap）、方向、车道范围、粒度、 天数、异常值区间、窗口长度、预测步长、CV 折数、随机种子、附加任务 AI 无法知道你的参数组合 → 生成的"通用答案"必然答非所问
② 数据指纹对你聚合后的序列做 SHA256 取前 12 位，报告与代码注释必须出现 抄别人的报告，指纹对不上（40 人实测 40 个指纹全不同）
③ 唯一锚点值任务书给出你口径下"折 1 的 Seasonal Naive MASE"， 教师用 --verify 一键复算AI 猜不到、同学抄不到；对不上即数字系编造
④ 可复现性审计教师随机指定某一折、换随机种子重跑你的代码 AI 生成的代码常跑不通、或换种子后数字对不上 —— 这是最致命的一击

10.2 分发策略：两个文件，各管一段

任务书由代码确定性生成，但这不等于把整个脚本丢给学生。关键在于 教师复算与学生自助必须得到完全一致的口径——否则学生会按错误参数做半天。 为此拆成两个文件：

文件发给谁能力为什么这样切
hw_task_selfservice.py学生 只有 --sid：查自己的任务书 学生自助，零教师维护；无批量能力，拿不到同班别人的口径与锚点值
hw_spec_generator.py教师留存 --batch 批量发放 / --verify 复算 / --audit 抽查 教师手里留一份原始副本，批改时一键复算学生的数字。此文件不发给学生
为什么教师版绝不能发？--batch 能一次列出全班每个人的 数据口径、指纹与锚点值。学生拿到后可直接查到同学的锚点值。虽然填进自己的报告 仍然对不上（教师按本人学号复算），但这等于把"审计底牌"交出去，也让机制失去威慑。 发学生版，留教师版。
无状态：两个版本口径必然一致
口径派生只依赖学号本身（sha256(学号) → 种子 → 抽参数）， 不含任何批次上下文。教师版直接 import 学生版的同一份函数， 所以"我复算"和"他自查"是同一段代码跑出来的——结构上杜绝口径漂移。
已实测学生版与教师版对同一学号输出：指纹与锚点值逐字一致。

10.4 你要做的四件事

  1. 数据重构：按任务书的方向 / 车道 / 目标变量 / 粒度 / 天数过滤聚合， 剔除区间外异常值，丢弃无数据的跨天空箱。算出并验证自己的数据指纹。
  2. 模型 A（Ridge-AR）：窗口 $\to$ horizon 的线性回归， 报告 alpha 的选择过程（必须用训练段内层验证，不许用测试集）。
  3. 模型 B（NLinear + 特征工程）：实例归一化（减窗口末值）， 特征至少含：滞后 1/2/3 步、滞后一个完整周期、过去半周期滚动均值与滚动标准差、时段指示变量。
  4. 滚动起源交叉验证：按任务书的折数 + 末端保留折，报告每折指标与均值 ± 标准差； 主指标 MASE，附 MAE / RMSE；必须打败 Seasonal Naive。

10.5 强制"思考痕迹"的三项要求

① 反事实实验（必须成对给数字）
人为制造一次数据泄露（例如：标准化改用全序列统计量 / 滚动统计窗口右移 1 格）， 报告"正确 MASE → 泄露后 MASE"这对数字，并解释涨幅从哪来。 防 AI 最有效——AI 编造解释很容易，但编出与你自己代码自洽的成对数字很难。

② 三个关键决定 + 放弃理由
报告必须写：你在建模中做了哪 3 个关键决定？每个决定的备选方案是什么，你为什么放弃了它？ （例如："周期我选了 48 而不是 24，因为……""我放弃了 SARIMA 因为……"） AI 最容易漏的就是"放弃理由"

③ 残差诊断结论
做一次 Ljung-Box 检验（逐折做，不许汇集），说明残差是否还有结构、若有则下一步该加什么特征。

① 特征/归一化用到未来信息；② 用测试集调参；③ 单次划分冒充交叉验证； ④ 指纹或锚点值与教师复算结果不一致且无法解释；⑤ 现场抽查无法运行自己的代码。
教师侧总工作量提示：--batch 一次生成全班任务书约 1-2 分钟； 批改时对每份报告跑一条 python hw_spec_generator.py --verify <学号>， 核对指纹与锚点值两个数字，即可筛出绝大多数代写/抄袭。 其余精力放在"三个决定 + 放弃理由"的质量上——那才是真正考察思考的地方。

11. 总结

                        时间序列预测
                            |
        +-------------------+-------------------+
        |                   |                   |
     看结构              选方法              严评估
        |                   |                   |
   ADF 只查单位根     基线: SeasonalNaive   滚动起源 CV
   ACF 读出周期 s    现代: NLinear/DLinear  主指标 MASE
   分解看三层         Patch:PatchTST       禁: 打乱/泄露
   残差查剩余        前沿: TSFM 零样本      审计: 可复现
        |                   |                   |
        v                   v                   v
   [!] 平稳≠无季节     [!] 简单模型常赢      [!] 数字要能复现
一句话总结：2026 年的时序预测，最重要的能力不是会调 Transformer， 而是知道该用什么、不该用什么。RNN 已退场、线性模型复兴、基础模型接管冷启动， 但 Seasonal Naive 这条基线依然是最锋利的检察官。先看清数据的结构（周期、平稳性、残差）， 再按数据特征选方法（不是按论文热度选），最后用不打乱时间、能被复现的方式诚实地评估。 flow.csv 的 192 个点给出的启示很朴素：贴合结构的简单模型， 常常打败结构错配的复杂模型。
